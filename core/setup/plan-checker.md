# plan-checker: 만들기 전에 계획이 조건을 다 채우는지 확인하는 AI

## 무엇을 하나

plan-checker 는 새 기능을 만들기 전에 planner 의 계획(`plan.json`)을 확인해요.
계획이 spec 의 다 됐다고 볼 조건(`spec.json`)을 전부 채우는지, 목표에서 거꾸로 따져 봐요.
빠진 조건이 있는지 찾아요. 테스트가 화면 요소를 찾을 이름표가 빠졌는지도 봐요.
절대 고치면 안 되는 파일을 건드리려는 계획도 찾아요.
문제를 찾아 알려 주기만 하고 계획은 고치지 않아요. 고치는 일은 planner 가 다시 해요.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/feature` | 3단계에서 계획을 확인할 때 불려요. 통과하지 못하면(FAIL) planner 에게 돌아가요. 세 번 넘게 반복되면 사용자에게 넘겨요 |

## 못 하는 것

- plan-checker 는 파일을 고치는 도구(Edit)가 없어요. 판정하는 쪽이 직접 고치면 자기가 고친 것을 자기가 통과시키게 돼요. 고치는 일은 planner 를 다시 불러서 해요
- 파일을 쓰는 도구(Write)는 결과 파일(`plan-check.json`)을 저장할 때만 써요. 코드 전체를 훑거나 git 을 쓰지도 않아요. 이 둘은 설명서의 규칙으로 막은 거예요. 도구로는 막혀 있지 않아요 (Write, Bash, Grep 이 있어요). 계획만 보는 단계라서 코드를 찾아보는 일은 explorer 가 해요

## 넘겨주는 것

plan-checker 는 결과를 이번 작업 폴더의 `plan-check.json` 에 적어요.
판정은 셋 중 하나예요. 통과(PASS), 주의할 점이 있지만 통과(PASS_WITH_NOTES), 통과 못 함(FAIL)이에요.
문제 목록과, 다 됐다고 볼 조건을 계획이 얼마나 채우는지도 적어요.
통과 못 하면 전체 순서를 관리하는 AI 가 문제 목록을 planner 에게 넘겨 다시 계획하게 해요.
주의할 점이 있지만 통과면, 중간 정도로 심각한 문제(MEDIUM)를 4단계 승인 요약에 넣어 사용자에게 보여 줘요.

## 여기에 넣으면 좋아지는 것

- 손대면 안 되는 파일 패턴을 알려 주세요. 모바일 앱이면 서명 설정과 자동 생성 코드, 웹이면 빌드 결과물과 잠금 파일(lock 파일), 서버라면 이미 배포한 데이터베이스 변경 파일(마이그레이션)이에요. 알려 주시면 plan-checker 가 그 파일을 건드리는 계획을 계획 단계에서 막아요 (FORBIDDEN_PLAN)
- 화면이 있는지, 테스트가 화면 요소를 무엇으로 찾는지 알려 주세요. 웹의 `data-testid`, 모바일의 `testTag` 같은 이름표예요. 그러면 plan-checker 가 이름표가 빠진 곳을 정확히 잡아요. 서버나 라이브러리라면 이 확인은 "해당 없음" 이 돼요
- 새 화면이나 새 API 가 갖춰야 할 구조가 코딩 규칙 문서에 적혀 있으면, plan-checker 가 구조가 빠졌는지(STRUCTURE_GAP) 근거를 갖고 판정해요
- 보고에서 강조할 항목을 알려 주세요. 예를 들어 외부 결제 서버를 거치는 흐름이 계획에서 빠진 것(SERVER_GAP)을 승인 요약 맨 앞에 두게 할 수 있어요. 판정 기준과 심각도는 바뀌지 않아요

|---|---|---|---|---|
| 1 | 사람이 직접 만들지 않은 코드가 있나요? 예를 들어 도구가 자동으로 만든 코드, 밖에서 복사해 온 외부 코드(vendor), 빌드 결과물 같은 것이에요 | generated 폴더, vendor 폴더, `.gitignore` 에 적힌 빌드 결과물 경로 | `forbidden_globs` | 막아 둔 파일이 없어요. 계획이 그 파일을 고치려 해도 plan-checker 가 막지 않아요 (FORBIDDEN_PLAN 이 안 나와요) |
| 2 | 사람만 손대야 하는 파일이 있나요? 예를 들어 서명 키, 배포 설정, 자동 빌드(CI) 설정, 이미 적용한 데이터베이스 변경 파일(마이그레이션) 같은 것이에요 | keystore 파일, `.env`, CI 설정 폴더, migrations 폴더 | `forbidden_globs` | 1번과 같아요. 계획이 그 파일을 고치려 해도 막지 않아요 |
| 3 | 계획 확인 보고에서 특히 앞에 두고 보여 줬으면 하는 항목이 있나요? 예를 들어 "외부 결제 서버 흐름이 빠진 건 맨 앞에 보여 주세요" 같은 것이에요. 판정 기준은 그대로이고, 보여 주는 순서와 강조만 바뀌어요 | 알 수 없어요 | `.claude/project/agents/plan-checker.md` | 하네스의 기본 보고 형식대로, 심각한 문제(HIGH)만 요약해요 |
