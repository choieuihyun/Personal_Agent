# verifier: 새로 만든 코드가 다 됐는지 검사하는 AI

## 무엇을 하나

verifier 는 새 기능 코드가 정말 "다 됐다" 고 할 수 있는지 검사해요.
빌드는 코드가 컴파일되는지만 봐요. verifier 는 컴파일로는 안 잡히는 것을 봐요.
먼저 이 프로젝트가 정한 완성 기준을 지켰는지 봐요.
다음으로 테스트가 누를 버튼에 이름표(예: data-testid)가 붙었는지 봐요.
새로 만든 화면이나 API 주소가 실제로 어딘가에 연결됐는지도 봐요.
verifier 는 문제를 찾아서 적기만 해요. 직접 고치지는 않아요.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/feature` | 7단계, 검사와 빌드를 하는 단계예요. 빌드를 맡은 builder 와 동시에 돌아요 |
| `/fix` | 불리지 않아요. 버그 수정에서는 빌드와 실제로 실행해 보는 검사만 해요 |

## 못 하는 것

- verifier 는 파일을 고치거나 새로 쓰지 못해요. 고치는 도구(Edit, Write)를 아예 주지 않았어요. 검사하는 AI 가 고치기 시작하면 무엇을 검사했는지 흐려지기 때문이에요
- 검사 결과도 파일로 쓰지 않아요. 결과를 돌려주기만 하고, 전체 순서를 관리하는 AI 가 `verifier.json` 으로 저장해요
- 명령 실행(Bash)은 완성 기준을 확인하는 스크립트를 돌릴 때만 써요. 빌드와 git 명령은 지시문으로 막혀 있어요

## 넘겨주는 것

verifier 는 `verifier.json` 을 넘겨요. 안에는 통과했는지, 찾은 문제 목록, 이번에 해당 없던 항목이 들어 있어요.
문제 하나마다 종류, 심각도, 파일, 줄 번호를 적어요.
전체 순서를 관리하는 AI 는 이 결과를 builder 의 빌드 결과와 합쳐서 판단해요.
중간 이상으로 심각한 문제(MEDIUM 이상)가 하나라도 있으면 실패예요.
실패하면 문제 목록이 코드를 고치는 AI(implementer)에게 그대로 넘어가요. implementer 는 그 목록을 보고 고쳐요.
가벼운 문제(LOW)는 보고에만 남고 실패로 치지 않아요.

## 여기에 넣으면 좋아지는 것

- 자동으로 확인할 수 있는 완성 기준을 알려 주세요. 앱이면 "화면 파일에는 미리보기 선언이 꼭 있어야 한다" 같은 규칙이에요. 웹이면 "컴포넌트에 색상 값을 직접 쓰면 안 된다", 서버면 "요청을 받는 파일에는 입력값 검사 호출이 꼭 있어야 한다" 같은 규칙이에요. 이런 규칙이 있으면 verifier 가 눈대중 대신 매번 같은 결과를 내요
- 새 코드를 만들면 등록해야 하는 파일을 알려 주세요. 웹의 라우트 설정, 앱의 매니페스트나 화면 이동 설정, 서버의 라우터, 의존성 주입 설정 같은 파일이에요. 알려 주시면 verifier 가 "만들었지만 아무도 안 부르는 코드" 를 덜 놓쳐요
- 코딩 규칙 문서가 없다면 "잘 된 예" 파일 하나를 알려 주세요. verifier 가 그 파일을 기준으로 코드를 판단해요

## 질문

| # | 사용자에게 할 질문 | 스캔으로 추측 | 저장 위치 | 안 채우면 |
|---|---|---|---|---|
| 1 | 코드를 보고 자동으로 확인할 수 있는 완성 기준이 있나요? 예를 들어 "화면 파일에는 미리보기 선언이 꼭 있어야 해요" 나 "컴포넌트 파일에 색상 값을 직접 쓰면 안 돼요" 같은 규칙이요. 어떤 파일에 어떤 글자가 꼭 있어야 하는지, 또는 있으면 안 되는지 알려 주세요 | 같은 종류의 파일(화면, 컴포넌트, 요청 처리 파일)에 공통으로 나오는 선언이나, 늘 피하는 코드 | `dod_checks` | 확인 스크립트가 "자동 확인을 못 했다" 고 알려요(exit 2). 이것을 통과로 치지는 않아요. verifier 는 코드를 읽고 판단하는 검사만 해요 |
| 2 | 새 화면이나 API 주소, 모듈을 만들면 어느 파일에 등록해야 하나요? 예를 들어 라우트 설정 파일, 화면 이동 설정, 서버 라우터, 의존성 주입 설정 파일 같은 곳이요 | 라우터, 매니페스트, 의존성 주입 설정 파일의 이름 | `.claude/project/agents/verifier.md` | verifier 가 새 코드 이름으로 코드 전체를 검색해서 부르는 곳을 찾아요. 등록 방식이 특이한 프로젝트라면 연결이 빠진 것을 놓칠 수 있어요 |
| 3 | 코딩 규칙 문서가 없다면, 코드를 판단할 때 기준으로 삼을 "잘 된 예" 파일이 있나요? 예를 들어 "로그인 화면 파일이 가장 깔끔해요" 같은 것이요 | 최근에 많이 고쳐졌고 구조가 가지런한 파일 | `.claude/project/agents/verifier.md` | verifier 가 일반 항목만 봐요. 파일 구조, 값을 코드에 직접 박았는지, 다 됐다고 볼 조건을 채우는 코드가 있는지만 확인해요 |
