# researcher: 공사 전에 새 자재의 공식 사용 설명서를 찾아와 요점만 건네는 조사원

## 무엇을 하나

옛 기술에서 새 기술로 옮겨 갈 때, 새 쪽의 최신 사용법을 공식 문서에서 찾아 정리해 준다.
무엇을 찾을지는 프로젝트의 전환 방향(예: JS -> TS, 클래스 컴포넌트 -> 훅)이 정한다.
찾은 곳이 공식 문서가 아니면 그 사실을 함께 밝힌다. 코드는 건드리지 않는다.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/modernize` | 1단계 탐색 + 리서치 (EXPLORING). explorer 와 동시에 불린다 |

## 못 하는 것

- 파일 읽기 도구 없음(Read, Grep, Glob 없음): 코드베이스 탐색은 explorer 몫이고 둘이 동시에 돌아 겹치면 낭비다
- 파일 수정, 코드 탐색, git 금지: 지시로 막음, 도구로는 안 막힘 (Bash 가 있다)
- 연결하지 않은 외부 지식 도구 호출: `tools:` 에 없는 도구는 부를 수 없다. 기본은 웹 검색과 웹 페이지 읽기뿐이다

## 넘겨주는 것

조회 항목, 핵심 내용, 주의사항(버전 차이, 곧 없어질 API), 참고 출처를 텍스트로 보고한다.
오케스트레이터가 정리해 implementer 에게 레퍼런스로 넘기고, implementer 는 그것을 보고 전환 코드를 쓴다.

## 여기에 넣으면 좋아지는 것

- 공식 문서 도메인: 안드로이드는 `developer.android.com`, 웹은 `react.dev` 나 `developer.mozilla.org`, 서버는 `docs.python.org` 나 `go.dev` 처럼 정해 주면 블로그가 섞이지 않는다
- 라이브러리 문서 서버 연결: 버전별 라이브러리 문서를 여는 MCP 서버를 붙이면 검색보다 먼저 정확한 버전의 문서를 조회한다
- 사내 지식베이스 연결: 사내 위키를 여는 MCP 서버를 붙이면 사내 공용 모듈 사용법도 찾아온다
- 버전 기준: "우리는 아직 React 17" 이나 "minSdk 24" 처럼 알려 주면 그보다 새로운 API 만 권하는 일을 줄인다

## 질문

| # | 사용자에게 할 질문 | 스캔으로 추측 | 저장 위치 | 안 채우면 |
|---|---|---|---|---|
| 1 | 믿을 만한 공식 문서 사이트는 어디인가요? | 의존성 파일(`package.json`, `build.gradle`, `pyproject.toml`)의 주요 프레임워크 -> 그 공식 도메인 | `learning.doc_domains` | 도메인 제한 없이 공식 문서를 우선할 뿐이라 블로그가 섞일 수 있다 |
| 2 | 라이브러리 문서를 조회하는 도구(버전별 문서를 여는 MCP 서버)를 연결할까요? | 설정된 MCP 서버 목록 | `tools:` | 웹 검색과 웹 페이지 읽기만으로 조회한다 |
| 3 | 사내 위키나 문서 저장소를 여는 도구를 연결할까요? | 설정된 MCP 서버 목록 | `tools:` | 사내 정보는 조회하지 못한다 |
| 4 | 지켜야 할 버전 하한이나, 쓰지 말아야 할 라이브러리가 있나요? | 의존성 파일의 버전 값, 최소 지원 버전 설정 | `.claude/project/agents/researcher.md` | 보충 없이 뼈대 절차대로 조회한다 |
