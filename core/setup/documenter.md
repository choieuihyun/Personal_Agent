# documenter: 코드가 바뀔 때마다 기능 설명 문서를 고쳐 적는 AI

## 무엇을 하나

documenter 는 코드가 바뀐 뒤에 그 기능을 설명하는 문서를 고쳐 적어요. 이 문서를 기능 묶음 설명 문서(DOMAIN.md)라고 불러요.
문서에는 바뀐 내용을 날짜와 함께 한 줄씩 쌓아요. 그 기능의 핵심 파일 목록도 새로 맞춰요.
문서가 아직 없으면 기본 틀로 새로 만들어요. 이때 코드로 확인한 것만 채우고 나머지 칸은 비워 둬요.
노트 앱이 연결돼 있으면 같은 내용을 노트 앱에도 올려요.
사소한 변경이면 "문서로 남길 필요 없음" 이라고 알리고 끝내요.

## 언제 불리나

| 커맨드 | 단계 |
|---|---|
| `/feature` | 8단계, 문서를 정리하는 단계예요. 새 기능은 늘 문서로 남길 대상이라 항상 불려요 |
| `/fix` | 버그 수정이 성공으로 끝난 뒤에 변경 크기를 보고 불러요. 클래스를 추가하거나 지웠을 때, 주요 로직을 바꿨을 때만 불려요 |

## 못 하는 것

- documenter 는 코드 파일을 고치지 않아요. 이건 지시문으로 막은 것이고, 도구로 막지는 못했어요(쓰기 도구 Write 가 있어요). 문서 담당이 코드를 고치면 무엇이 바뀌었는지 기록할 기준이 흐려져요
- 명령 실행과 검색 도구(Bash, Grep, Glob)가 없어요. 어느 기능 묶음인지는 전체 순서를 관리하는 AI 가 계산해서 넘겨줘요. documenter 가 직접 계산하지 않아요
- git 명령은 쓰지 않아요. 저장소 상태는 전체 순서를 관리하는 AI 만 바꿔요
- 노트 앱에 쓰는 도구는 연결하기 전까지 없어요. 그동안은 내 컴퓨터의 문서 파일에만 적어요. 연결할지는 /setup 이 documenter 차례에 여쭤봐요

## 넘겨주는 것

documenter 는 일이 끝나면 다음을 알려 줘요.
고치거나 새로 만든 문서의 위치, 새로 적은 변경 기록, 비워 둔 칸, 노트 앱에 올렸는지 여부예요.
전체 순서를 관리하는 AI 는 이 내용을 마지막 보고에 넣어요.
이렇게 쌓인 기능 묶음 설명 문서는 다음 작업의 바탕 지식이 돼요.
explorer, planner, implementer, verifier 같은 다른 AI 들이 일을 시작하기 전에 이 문서를 읽어요.

## 여기에 넣으면 좋아지는 것

- 문서를 모을 폴더를 정해 주세요. 앱은 `docs/features/`, 웹은 `docs/pages/`, 서버는 `docs/services/` 처럼 정해 주면 documenter 가 거기에 쌓아요
- 팀이 노트 앱에서 문서를 본다면 알려 주세요. 노트 앱 안에서 문서가 들어갈 폴더 위치와 쓰기 도구를 알려 주시면, 내 컴퓨터의 문서와 같은 내용을 노트 앱에도 올려요
- 문서로 남길지 말지 정하는 기준을 조정할 수 있어요. 예를 들어 서버는 "API 주소를 추가하면 늘 기록", 웹은 "스타일만 바뀌면 기록하지 않음" 같은 규칙이에요
- 기능마다 처음 알아야 할 지식을 먼저 적어 두세요. 깨지면 안 되는 규칙이나 자주 틀리는 곳 같은 거예요. documenter 는 이런 내용을 지어내지 않고 비워 둬요. 사용자가 기능 묶음 설명 문서에 먼저 적어 두시면 documenter 가 그 위에 이어서 쌓아요
